## 2. Configuration System

### How it loads

`config.py` defines the dataclass `AnalysisConfig` with defaults. At import time, `load_config_from_file('config.json')` overlays the JSON, then `_validate_config` runs; on validation failure it rolls back. `update_config(**kwargs)` is the only thread-safe runtime mutator (uses `_CONFIG_LOCK`, validates, rolls back).

**Production overrides:** see [`docs/config-contract.md`](../../docs/config-contract.md) for intentional differences between `config.py` defaults and live `config.json` (e.g. `HARD_STOP_PCT=-0.08`, `ROTATION_FRICTION_POINTS=3.0`, `REGIME_FLIP_COOLDOWN_DAYS=5`).

### Validation rules (selected)

- Threshold ordering: `STRONG_BUY_THRESHOLD > BUY_THRESHOLD > HOLD_THRESHOLD > SELL_THRESHOLD`.
- Weight sum: `FUNDAMENTAL_WEIGHT + TECHNICAL_WEIGHT + UNDERVALUATION_WEIGHT == 1.0` (tol 0.01), all non-negative.
- Ranges: see `_VALIDATION_RULES` dict in `config.py` (covers ~45 keys including `HARD_STOP_PCT`, `SOFT_STOP_PCT`, `ROTATION_FRICTION_POINTS`, `V2_IC_BLEND_7D`, etc.).

### Important keys (grouped)

- **Performance**: `MAX_WORKERS=8`, `BATCH_SIZE=5`, `TIMEOUT_SECONDS=120`, `RETRY_ATTEMPTS=3`, `REQUEST_DELAY=0.5`, `CACHE_*`.
- **Scoring**: `FUNDAMENTAL_WEIGHT=0.4`, `TECHNICAL_WEIGHT=0.3`, `UNDERVALUATION_WEIGHT=0.3`. (Validation-only; hybrid engine uses regime-adaptive weights at runtime.)
- **Recommendation thresholds**: `STRONG_BUY=70`, `BUY=60`, `HOLD=50`, `SELL=40`, `UNDERVALUED_THRESHOLD=65`.
- **Hysteresis & smoothing**: `HYSTERESIS_BUFFER=3.0`, `HYSTERESIS_PROXIMITY_BOOST=1.5`, `SCORE_SMOOTHING_WEIGHT=0.55` (`_BEAR=0.50`, `_DOWN=0.75`, `_UP=0.45`), `SCORE_SMOOTHING_MAX_AGE_DAYS=3`. `UNIDIRECTIONAL_HYSTERESIS=False` (v3 Layer 3 toggle — when True, only upgrades are buffered, downgrades fall through immediately).

## 3. Scoring Engines

### v1 (`HybridOptimizedScoringEngine`)

- Audit baseline. Internal version banner: V5.2 (`hybrid_optimized_scoring.py:30`).
- Sector and regime multipliers neutralised (validation showed 70% of IC was sector bias).
- `_CALIBRATED_WEIGHTS_PATH = 'data/calibrated_weights.json'`. File absent in current repo → engine uses V5.2 regime defaults; v1 score remains the audit baseline.
- Eight components: `fundamental_quality`, `growth` (Rule 3a), `value` (Rule 3a), `momentum_technical`, `volume_strength`, `multi_timeframe`, `ml_signal`, `risk_adjustment`. v2 reuses the same component functions.

### v2 (`HybridOptimizedScoringEngineV2`)

- Subclass; **isolated state**:
  - Global: `_CALIBRATED_WEIGHTS_PATH = 'data/calibrated_weights_v2.json'`.
  - Per-regime (Tier C2): `_REGIME_WEIGHT_PATH_TEMPLATE = 'data/calibrated_weights_v2_{regime}.json'` for `BULL` / `BEAR` / `SIDEWAYS`. Loader prefers the regime-specific file matching the live `MarketRegimeDetector` regime, falls back to global.
- Calibration: Spearman IC vs `return_7d` and `return_30d`, blended `DEFAULT_BLEND_7D=0.80`; auto-shifts to `DEFAULT_BLEND_7D_AT_TRIGGER=0.60` when `n_30d >= BLEND_30D_TRIGGER_SAMPLES=100`.
- Drops components below `MIN_ABS_IC=0.01`. Normalises by sum of |IC|. Caps any single |weight| at `MAX_ABS_SINGLE_WEIGHT=0.45`.
- **Negative weights allowed** — the deliberate v2 difference.
- Min total samples: `MIN_SAMPLES=50`; per-component minimum joint sample size: 20.
- Per-regime calibration uses relaxed floor `MIN_SAMPLES_PER_REGIME=30`.
- **Cache TTL: 14 days** (warning when age > 7d). Extended from the original 3-day TTL after silent fallback regressions (weekend gaps).
- Component map (current, 8 entries): `fundamental_quality`, `momentum_technical`, `volume_strength`, `multi_timeframe`, `ml_signal`, `risk_adjustment`, `growth`, `value`. Each maps to `hybrid_*` history column primary and legacy flat column fallback.
- Output JSON contains: `weights`, `ics_7d`, `ics_30d`, `ics_blended`, `blend_7d`, `sample_size_7d`, `sample_size_30d`, `updated`, `engine: 'v2'`.

### Live mode (current)

`cfg.V2_SHADOW_MODE=False` (config.json) — v2 drives actions. v1 still runs and its score is logged for audit. History columns `score` and `score_v2` both populated; allocation/Excel sheets driven by v2.

## 4. v2 Promotion State Machine

```
nightly: calibrate_v2_weights.py [--source recommendation_history|historical_outcomes] [--per-regime]
                                    →  data/calibrated_weights_v2.json
                                    →  data/calibrated_weights_v2_{BULL,BEAR,SIDEWAYS}.json (when --per-regime)

nightly: v2_promotion_check.py   [--mode forward|historical] [--window-days 60] [--evaluate]
                                    →  data/v2_promotion_status.json
                                       ├─ mode, window_days
                                       ├─ eligible_today (bool)
                                       ├─ consecutive_eligible_days  (forward only; resets to 0 on miss)
                                       ├─ days_required_for_promotion (30 forward, 0 historical)
                                       └─ promotion_ready

manual:  promote_v2.py [--dry-run|--force]
                                    →  flips V2_SHADOW_MODE, sets V2_PROMOTION_DATE,
                                       backs up old config.json
```

### Eligibility criteria (strict v3 gating, `v2_promotion_check.py`)

All must be True for `eligible_today` (forward mode):
1. `v2 IC_30d (Spearman) >= 0.05`
2. `v2 Q5−Q1 spread >= 3.0 pp`
3. `v2 sample size n_30d >= 200`
4. `v2 SELL hit rate (30d) >= 50%` (dropped in historical mode — bottom-quintile proxy is too noisy on multi-year drift)
5. `v2 weights file present` and `weights_age_days <= 7`

`promotion_ready` rules:
- **Forward mode** (live): True only after `consecutive_eligible_days >= CONSECUTIVE_DAYS_REQUIRED=30`.
- **Historical mode**: True on any single passing run; consecutive-day gate bypassed (we're evaluating against the full historical dataset, not waiting forward).

The legacy `edge_q5_v2_minus_v1_pp` metric is still emitted in the criteria block but no longer gates.

### Rollback

`promote_v2.py` writes `config.json.pre_v2_promotion_<ts>.bak`. To roll back: `cp config.json.pre_v2_promotion_<ts>.bak config.json`. The pre-v2 backup from 2026-05-13 is at `config.json.pre_v2_promotion_20260513_005851.bak`.

## 5. Recommendation & Action Lifecycle

1. Universe filter (`src/universe_filter.filter_universe`) drops excluded instruments and illiquid names.
2. Per-symbol bundle: `StockDataBundle` does a single yfinance pull for 5Y/2Y/1Y/6mo/3mo/1mo + `.info`.
3. Components scored → blended via v2 (live) with v1 audit shadow. Per-regime v2 weights chosen if available; otherwise global v2 weights; otherwise v2 silently falls back to v1 regime defaults (logged WARN).
4. Adaptive regime strategy adjusts weights and gross exposure.
5. Score smoothing (regime-aware; `_BEAR` weights for bear regime), hysteresis at thresholds (`UNIDIRECTIONAL_HYSTERESIS` flips behaviour when True).
6. Hard-stop evaluation (`_evaluate_hard_stop(profit_pct, score, rsi, pattern_signal, cfg, sleeve, market_regime)`) — tiers: `EMERGENCY` / `HARD_STOP` / `SOFT_STOP` / `NONE`. CORE sleeve short-circuits to HOLD (no price stop). BEAR regime tightens thresholds. `HARD_STOP_PURE_PNL` (or `PAPER_TRADING_MODE`) disables the score/RSI/pattern override.
7. Trailing stop (Contract Rule 6b) checks `peak * (1 - TRAILING_STOP_PCT)` (bear `0.10`) against `data/booking_history.json` peak; emits `TRAILING_STOP` exit when underwater from peak AND in profit.
8. Scale-out (Contract Rule 5): fires when position up ≥`SCALE_OUT_PROFIT_THRESHOLD=0.15` AND v2 score down ≥`SCALE_OUT_V2_DROP_PTS=10` from peak; liquidates `SCALE_OUT_FRACTION=0.20`.
9. Rotation gate (`_should_rotate`) — requires score edge ≥ 5 pp AND holding weakness (low score OR high RSI OR weak P&L).
10. Action assigned (canonical enum — see §5.3).
11. Allocation built (sector caps, cap-tier limits, concentration check).
12. Excel + HTML report rendered.
13. History append (`recommendation_history.py`) with cooldown and flip-flop guard. Same-day re-runs with different action OVERWRITE (DQ-NATALUM policy); same-day with same action is idempotent (only backfills optional columns).

### 5.1 Hard-stop tier table

Source of truth: `EnhancedTop200StockAnalyzer._evaluate_hard_stop` (analyze_top200_stocks_enhanced.py:430).

Define `override = (score >= HARD_STOP_OVERRIDE_SCORE=65) AND (rsi > 40) AND (pattern_signal != 'bearish')`. When `HARD_STOP_PURE_PNL=True` or `PAPER_TRADING_MODE=True`, `override` is forced `False` (pure P&L exit).

BEAR / VOLATILE regime tightens (additive in pp space):
- `EMERGENCY: -15% → -12%` (`_BEAR_EMERGENCY_TIGHTEN=0.03`)
- `SOFT_STOP: -10% → -8%`   (`_BEAR_SOFT_TIGHTEN=0.02`)
- `HARD_STOP: -7%  → -5%`   (`_BEAR_HARD_TIGHTEN=0.02`)

CORE sleeve: short-circuits to `tier='NONE', action='HOLD'` BEFORE any price-stop evaluation. CORE exits only on thesis break.

Evaluation is ordered top-to-bottom; first match wins.

| profit_pct (loss) | override | tier | action | book_pct | notes |
|---|---|---|---|---|---|
| ≤ EMERGENCY_THR (−0.15, BEAR −0.12) | * | EMERGENCY | SELL | 100 | Hardcoded; capital preservation override. NOT from `EMERGENCY_EXIT_LOSS` config. |
| ≤ SOFT_STOP_PCT (−0.10, BEAR −0.08) | True | SOFT_STOP | REDUCE | 50 | Override extends to half-exit. |
| ≤ SOFT_STOP_PCT | False | HARD_STOP | SELL | 100 | No override → full exit. |
| ≤ HARD_STOP_PCT (−0.07, BEAR −0.05) | True | NONE | HOLD | 0 | Override extends stop to SOFT level. |
| ≤ HARD_STOP_PCT | False | HARD_STOP | SELL | 100 | No override → full exit. |
| > HARD_STOP_PCT | * | NONE | HOLD | 0 | Within risk tolerance. |

Note: `cfg.EMERGENCY_EXIT_LOSS=-0.30` and `EMERGENCY_TIER_*` knobs are used by a separate (sliding-scale) exit codepath, not by `_evaluate_hard_stop`. Don't conflate them.

### 5.2 Rotation gate

Source of truth: `EnhancedTop200StockAnalyzer._should_rotate` (analyze_top200_stocks_enhanced.py:841).

Rotation is allowed iff **both**:
1. `candidate_score - holding_score >= ROTATION_FRICTION_POINTS` (default 5.0).
2. Holding shows weakness — at least one of:
   - `holding_profit_pct < 0.05`
   - `holding_rsi > 75`
   - `holding_score < 50`

### 5.3 Action canonicalisation (`recommendation_history._normalize_action`)

Order matters — first match wins:

| Keyword in input | Canonical output |
|---|---|
| `EXIT` | `EXIT` |
| `EMERGENCY` or (`SELL` and not `CONSIDER`/`WEAK`) | `SELL` |
| `STOP LOSS` | `SELL` |
| `SWAP` | `SWAP` |
| `INCREASE` or `MOMENTUM PLAY` | `INCREASE` |
| `STRONG BUY` / `STRONG_BUY` | `STRONG BUY` |
| `NEW POSITION` | `NEW POSITION` |
| `BUY` (and not `WEAK`) | `BUY` |
| `SCALE_OUT` / `SCALE OUT` | `SCALE_OUT_20` |
| `REDUCE` or `BOOK` | `REDUCE` |
| `WEAK SELL` / `CONSIDER SELL[ING]` | `WEAK SELL` |
| `HOLD` / `KEEP` / `WATCH` | `HOLD` |
| (none) | passthrough (cleaned) |

Suite 1 baseline `allocation_actions` (the contract subset) is:
`HOLD, SELL, INCREASE, NEW POSITION, WATCHLIST, EXIT NOW - Heavy exhaustion, HIGH MOMENTUM NEW POSITION`.

## 9. Coding Standards (this repo)

- Always `from config import get_config` — never `AnalysisConfig()` locally (MI-05).
- Avoid emoji in code, comments, and commit messages (legacy emoji-heavy modules / sheet names exist; do not propagate beyond the baseline-snapshot fixture).
- No narrating comments (`# import x`, `# return result`). Comments must capture intent or non-obvious constraints.
- Type hints + dataclasses are encouraged; match existing module style.
- New scripts go under `scripts/` (one-off utilities) or `tools/` (interactive helpers); do not add new top-level entry points.
- New tests go under `tests/`; integration tests under `tests/integration/`, unit under `tests/unit/`.
- Backups: `promote_v2.py` writes `.pre_v2_promotion_<ts>.bak`. Follow the same `<original>.<reason>_<ts>.bak` convention if writing other migrators.

## 10. Quick Pointers

- "Where is action X assigned?" → grep in `analyze_top200_stocks_enhanced.py` for the action string; cross-check `recommendation_history._normalize_action` (§5.3).
- "Where do regime weights come from?" → `adaptive_market_strategy.AdaptiveMarketRegimeStrategy`, gated by `MarketRegimeDetector` output cached in `data/last_known_regime.json`. v2 additionally picks `data/calibrated_weights_v2_{regime}.json` when present.
- "How is a sell triggered?" → `_evaluate_hard_stop` (loss-driven, sleeve+regime-aware) or `EarlyBreakoutDetector.detect_momentum_exhaustion` (RSI exhaustion) or trailing stop (peak drawdown via `booking_history.json`) or score-threshold + hysteresis. Scale-out (Rule 5) generates `SCALE_OUT_20`.
- "How do I add a new component to scoring?" → add `hybrid_<name>` column to history writer in `recommendation_history.py`, update `component_map` in `hybrid_scoring_v2.calibrate_weights_from_outcomes` AND the `component_pairs` list in `scripts/calibrate_v2_weights.py`, add the per-component scorer to v1 (`hybrid_optimized_scoring.py`), extend `tests/test_v2_regression.Suite5/Suite11` if isolation/calibration surface impacted.
- "How do I roll v2 back?" → `cp config.json.pre_v2_promotion_<ts>.bak config.json` (most recent pre-v2 backup: `20260513_005851`).
